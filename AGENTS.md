# AGENTS.md

## Проект

Виртуальный джойстик для Linux, для игры в MSFS-2020.

## Требования

- Минимальный код на C, без сторонних библиотек (только заголовки ядра и libc).
- Ввод: `evdev` (чтение клавиатуры). Вывод: `uinput` (виртуальный джойстик).
- 4 оси — перечень в разделе «Оси».
- Диапазон каждой оси: −32768…32767.
- Шаг за одно нажатие: 5% полного диапазона (3276 единицы). Результат ограничивается границами оси.
- Оси запоминают положение, пока запущена программа (значение не сбрасывается).
- Реагировать только на нажатие клавиши (`EV_KEY`, `value == 1`). Удержание (автоповтор, `value == 2`) и отпускание (`value == 0`) игнорировать.
- Захват клавиатуры (`EVIOCGRAB`) запрещён. События продолжают поступать остальным приложениям как обычно.
- Раскладка зашита в код. Конфигурационных файлов нет.

## Оси

| Ось      | Назначение           | Код evdev |
|----------|----------------------|-----------|
| X        | поверхности самолёта | `ABS_X`   |
| Y        | поверхности самолёта | `ABS_Y`   |
| Z        | поверхности самолёта | `ABS_Z`   |
| Throttle | тяга                 | `ABS_RZ`  |

Диапазон и шаг каждой оси — в разделе «Требования».

## Таблица кнопок (уменьшить / сброс / увеличить)

| Ось      | Уменьшить  | Сброс        | Увеличить   |
|----------|------------|--------------|-------------|
| X        | `KEY_KP4`  | `KEY_KP5`    | `KEY_KP6`   |
| Y        | `KEY_KP8`  | `KEY_KP7`    | `KEY_KP2`   |
| Z        | `KEY_KP1`  | `KEY_KP7`    | `KEY_KP3`   |
| Throttle | `KEY_KP0`  | `KEY_KPPLUS` | `KEY_KPDOT` |

- Имена клавиш — из `linux/input-event-codes.h` (grep KEY_KP /usr/include/linux/input-event-codes.h).
- Сброс throttle: `KEY_KPPLUS` — свободная клавиша NumPad, не задействованная в остальных операциях. NumLock, `KEY_KPASTERISK`, `KEY_KPSLASH`, `KEY_KPENTER` и `KEY_KPMINUS` оставлены системным функциям.
- `KEY_KP7` сбрасывает одновременно Y и Z — как в исходной раскладке.

## Внутренние команды

Таблица «клавиша → команда» вшита в код. Имена команд:

| Ось      | Уменьшить        | Сброс             | Увеличить         |
|----------|------------------|-------------------|-------------------|
| X        | `x_axis_down`    | `x_axis_center`   | `x_axis_up`       |
| Y        | `y_axis_down`    | `y_axis_center`   | `y_axis_up`       |
| Z        | `z_axis_down`    | `z_axis_center`   | `z_axis_up`       |
| Throttle | `throttle_down`  | `throttle_center` | `throttle_up`     |

Значения команд: `*_up` — увеличить, `*_down` — уменьшить, `*_center` — обнулить ось.

## Права доступа

Программе нужны два доступа: **читать** `/dev/input/event*` (события клавиатуры) и **писать** в `/dev/uinput` (виртуальный джойстик). Ниже — как устроены права, кто их выдаёт и зачем нужен каждый из них.

**Как устроены права.** Устройства в Linux — обычные файлы с правами (`владелец:группа` + режим). Доступ проверяется при `open()`: нет нужного права — программа не может пользоваться устройством. Права выдаются по принципу минимума: пользователю — только то, что необходимо, без полных прав root.

**Кто выдаёт права.**

- **udev** — при появлении устройства применяет правила (системные и из пакетов): выставляет владельца и группу по умолчанию (для ввода обычно `root:input`, чтение — группой `input`) и ставит метки. Метка `uaccess` означает: «устройство можно выдать активной сессии».
- **logind** — видит метку `uaccess` и активную сессию пользователя (seat) и добавляет ACL — запись `user:<имя>:rw-`. ACL дополняет обычные права: виден через `getfacl`, помечается `+` в выводе `ls`.
- **администратор** — вручную: группа `input` (`usermod -aG`), `setfacl`, запуск от root.

**Зачем чтение `/dev/input/event*`.** Из этих файлов ядро отдаёт поток событий ввода — записи `struct input_event` (тип, код, значение). Программа — потребитель потока: читая события `EV_KEY`, она узнаёт нажатие клавиши (`KEY_KP4`) и двигает ось. Проверяется право на чтение в момент `open()`; без него событий нет — оси мёртвые.

**Зачем запись в `/dev/uinput`.** `uinput` — интерфейс ядра для создания виртуальных устройств ввода. Программа пишет туда:

- команды настройки (ioctl `UI_SET_EVBIT`, `UI_DEV_SETUP`, `UI_ABS_SETUP`, `UI_DEV_CREATE`) — объявляет джойстик: четыре оси `ABS_*`, диапазон −32768…32767;
- события — текущие значения осей (`EV_ABS` + `SYN_REPORT`); игра читает их как события настоящего джойстика.

Без права на запись виртуальное устройство не создаётся — программе нечего отдавать игре.

**Проверка:** `getfacl /dev/uinput /dev/input/event*`.

**На этой машине:**

- `/dev/uinput` — метка `uaccess` есть, ACL `user:serg:rw-`: запись доступна без root.
- `/dev/input/event*` — метка `uaccess` стоит не у всех: у Evision она выдана правилом из `/etc/udev/rules.d/60-openrgb.rules` (пакет OpenRGB), у Logitech метки нет — ACL нет, доступ только группе `input`.
- Следствие: без root программа читает только устройства с ACL. Если среди них нет клавиатуры, которая реально шлёт события (например, физическая захвачена keyd) — запуск от root либо добавить пользователя в группу `input`: `sudo usermod -aG input <имя>` с последующим перелогином.

## Заголовки и версия ядра: UAPI — стабильный ABI

Программа подключает `/usr/include/linux/input.h` и `/usr/include/linux/uinput.h`, **не обращая внимания на версию запущенного ядра**. Это допустимо.

- Заголовки ставит не ядро, а отдельный пакет **`linux-libc-dev`** — обновляется через apt независимо от того, какое ядро крутится. Проверка версий:

  ```sh
  dpkg -s linux-libc-dev | grep Version   # версия заголовков
  uname -r                                # версия рабочего ядра
  ```

- На этой машине: заголовки **6.8.0**, рабочее ядро **7.2.6** — несовпадение нормально и работает.
- Причина — **UAPI: стабильный ABI «ядро ↔ пользовательское ПО»**. Заголовки `/usr/include/linux/` описывают контракт: раскладки структур (`input_event`), номера ioctl (`UI_DEV_SETUP`, `EVIOCGBIT`), коды (`KEY_*`, `ABS_*`). Ядро обязано поддерживать этот контракт независимо от своей версии: что описывают старые заголовки, то новое ядро продолжает понимать.
- Другая система заголовков — `/lib/modules/$(uname -r)/build` (→ `/usr/src/linux-headers-<версия>`): внутренний API ядра для сборки модулей (драйверов), требует точного совпадения с запущенным ядром. Эта программа их не использует.
- Крайний случай: интерфейс, появившийся **позже** версии `linux-libc-dev` — в старых заголовках его нет, тогда пакет заголовков обновляют. Всё, что использует программа (`EVIOCGBIT`, uinput-ioctl, `KEY_*`, `ABS_*`), существует задолго до 6.8.

## Проверка

Проверка идёт по уровням: от логики до игры. Каждый уровень предыдущий считается обязательным.

### 1. Сборка

```sh
make
```

Должна собраться без предупреждений (`-Wall -Wextra`).

### 2. Логика — `make test`

```sh
make test
```

`test_joy.c` подключает `joy-for-msfs2020.c` напрямую и подаёт синтетические события `EV_KEY`, без реальной клавиатуры и uinput (запись идёт в `/dev/null`) — права не нужны. Проверяется:

- шаг оси 3276 и ограничение границами −32768…32767 с обеих сторон;
- сброс командой `*_center`;
- реакция только на нажатие: автоповтор (`value == 2`) и отпускание (`value == 0`) оси не двигают;
- защита от двойного `down` с двух устройств (повторная клавиша игнорируется до отпускания);
- `KEY_KP7` даёт две команды — сброс Y и Z одновременно;
- клавиши вне раскладки ничего не двигают.

Выход: `все проверки пройдены`.

### 3. Устройство создаётся

```sh
sudo ./joy-for-msfs2020 &
grep joy-for-msfs2020 /proc/bus/input/devices
```

Должна появиться строка `N: Name="joy-for-msfs2020"` — значит, uinput-устройство создано и видно системе.

### 4. Живой тест осей — evtest

Нужен `evtest` (установить: `sudo apt install evtest`). В отдельном терминале:

```sh
sudo evtest
```

Выбрать устройство `joy-for-msfs2020` и нажимать клавиши таблицы раскладки, сверяя события:

| Нажатие        | Ожидаемое событие                         |
|----------------|-------------------------------------------|
| `KEY_KP4`      | `EV_ABS ABS_X` −3276 (каждое — ещё −3276) |
| `KEY_KP5`      | `EV_ABS ABS_X` 0                          |
| `KEY_KP7`      | `EV_ABS ABS_Y` 0 **и** `ABS_Z` 0          |
| `KEY_KP8`      | `EV_ABS ABS_Y` −3276                      |
| `KEY_KP1`      | `EV_ABS ABS_Z` −3276                      |
| `KEY_KP0`      | `EV_ABS ABS_RZ` −3276 (тяга вниз)         |
| `KEY_KPPLUS`   | `EV_ABS ABS_RZ` 0                         |
| `KEY_KPDOT`    | `EV_ABS ABS_RZ` +3276                     |

Каждому изменению оси сопутствует `EV_SYN SYN_REPORT`. Дополнительно проверить: удержание клавиши ось не двигает (автоповтор игнорируется); значения сохраняются между нажатиями.

`evtest` читает устройство параллельно с программой — это не мешает (события копируются всем читателям).

Выход из программы — `Ctrl+C` в терминале, где она запущена; устройство `joy-for-msfs2020` исчезает из `/proc/bus/input/devices`.

### 5. В игре

Запустить MSFS и убедиться, что джойстик `joy-for-msfs2020` виден с четырьмя осями, а в настройх управления оси двигаются при нажатии клавиш NumPad.
